# GrievAI – AI-Powered Smart Grievance Analysis and Resolution Support System

GrievAI is a student grievance analysis and resolution-support project. It uses text classification and rule-based logic to analyse a grievance, identify its category, estimate its priority, map it to a responsible department, and recommend a suitable action. A Streamlit web application is included in the implementation notebook.

## Project objectives

- Classify student grievances into predefined categories using their written descriptions.
- Identify urgency levels such as **Critical**, **High**, **Medium**, and **Low**.
- Assign a responsible department based on the predicted grievance category.
- Recommend a next action for the concerned department.
- Provide a simple web interface for submitting and reviewing grievances.

## How it works

1. **Input:** A student enters a grievance in natural language.
2. **Category prediction:** A TF-IDF text representation and Logistic Regression classifier predict the grievance category.
3. **Priority assessment:** Rule-based keyword checks estimate the urgency and assign a priority score.
4. **Department mapping:** The predicted category is mapped to a responsible department.
5. **Action recommendation:** The system generates a recommended action, including escalation guidance for emergency-related text.
6. **Record keeping:** The Streamlit application stores submitted grievance records in `grievances.csv`.

> Priority assignment and emergency detection in this implementation are rule-based. They are decision-support suggestions and should be reviewed by the responsible staff, especially for safety-related reports.

## Model and processing approach

### 1. Text classification

The notebook uses a Scikit-learn pipeline containing:

- `TfidfVectorizer` with lowercasing, English stop-word removal, and unigram/bigram features.
- `LogisticRegression` with an increased iteration limit.

The data is split into training and test sets using an 80:20 split, a fixed random state, and stratification by category.

### 2. Priority assessment

A keyword-based function assigns one of four priority labels:

- **Critical** – emergency or safety-related indicators.
- **High** – urgent language or major service disruptions.
- **Medium** – general problems, issues, or difficulties.
- **Low** – information requests, suggestions, or feedback.

The implementation also returns a numeric priority score and a reason for the assigned level. These are heuristic rules, not a separately trained priority-prediction model.

### 3. Department and action mapping

The implementation maps grievance categories to responsible departments and recommended actions. Emergency-related terms are handled with an escalation recommendation.

## Run the project in Google Colab

1. Open the notebook `Mini_Project_implementation_clean.ipynb` in Google Colab.
2. Run the installation cell.
3. When the upload cell appears, upload `Datasetprojpowerbi.csv`.
4. Run the notebook cells in order so the data is prepared and the category model is trained.
5. Run the model-saving cell to generate `category_model.pkl`.
6. Run the cell that writes `app.py`.
7. Run the Streamlit launch and Colab proxy cells to open the web application.

The notebook includes Colab-specific commands for starting Streamlit and exposing it through the Colab environment. Those commands are intended for Google Colab and may need adjustment when running locally.

## Run the Streamlit app locally

After generating `app.py` and `category_model.pkl`, place both files in the same project directory. Install the dependencies and start Streamlit:

```bash
pip install streamlit scikit-learn pandas numpy joblib matplotlib
streamlit run app.py
```

Open the local address printed by Streamlit in your browser.

If you run the app outside Colab, make sure the trained model file `category_model.pkl` is present in the same directory as `app.py`.

## Limitations

- Category predictions depend on the quality, coverage, and balance of the labelled training data.
- Priority assignment uses predefined keywords and may not understand context, negation, spelling variations, or subtle urgency.
- Department and action recommendations are based on predefined mappings.
- The system is a decision-support prototype, not a replacement for human review or an official emergency-response process.
- The dataset may contain demographic or personal information; handle it responsibly and do not publish sensitive records.
